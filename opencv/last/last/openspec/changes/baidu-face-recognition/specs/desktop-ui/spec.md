## ADDED Requirements

### Requirement: 主窗口与功能页签

系统 SHALL 提供一个桌面主窗口，包含「人员注册」「单人识别」「人脸库管理」三个功能页签，使用者可在其间自由切换。

#### Scenario: 窗口启动

- **WHEN** 程序启动且配置合法
- **THEN** 主窗口打开并默认停留在人员注册页，三个页签均可见

#### Scenario: 页签切换

- **WHEN** 使用者点击任一页签
- **THEN** 主区域切换到对应功能界面，其他页签的已填写状态不被清空

#### Scenario: 配置缺失时启动失败提示

- **WHEN** 程序启动时 `.env` 中缺少 API Key 或 Secret Key
- **THEN** 系统弹出明确的配置错误提示并给出填写指引，而不是直接崩溃退出

### Requirement: 摄像头实时预览

系统 SHALL 在注册与识别界面提供摄像头画面的实时预览，并允许使用者将当前画面抓取为待处理图片。

#### Scenario: 预览画面持续刷新

- **WHEN** 摄像头可用且相关页签处于打开状态
- **THEN** 预览区域持续显示最新画面

#### Scenario: 抓拍当前画面

- **WHEN** 使用者点击抓拍按钮
- **THEN** 当前预览画面被固定为待处理的图片，并给出已被选取的视觉反馈

#### Scenario: 摄像头不可用

- **WHEN** 程序无法打开摄像头
- **THEN** 界面提示摄像头不可用，禁用抓拍入口，并保留从文件选择图片的替代路径

#### Scenario: 程序退出时释放摄像头

- **WHEN** 使用者关闭主窗口
- **THEN** 采集线程停止且摄像头设备被释放，不残留占用

### Requirement: 耗时操作不阻塞界面

系统 SHALL 在后台线程执行摄像头采集与全部网络请求，并仅通过主线程更新界面。

#### Scenario: 网络请求期间界面保持响应

- **WHEN** 任一云端接口调用正在进行
- **THEN** 窗口仍可拖动、页签仍可切换，界面不发生冻结

#### Scenario: 忙碌状态防重复提交

- **WHEN** 一个操作正在进行中
- **THEN** 触发该操作的按钮被置为禁用或忙碌状态，避免重复发起请求而浪费配额

#### Scenario: 操作完成后回到就绪状态

- **WHEN** 操作成功或失败返回
- **THEN** 按钮恢复可用，界面呈现本次操作的结果

### Requirement: 操作结果与状态反馈

系统 SHALL 在界面上提供持续的运行状态提示，并对每次操作给出明确的成功或失败反馈。

#### Scenario: 展示当前状态

- **WHEN** 任一操作开始、进行或结束
- **THEN** 状态区域显示相应的文字说明（如"正在识别…"、"注册成功"）

#### Scenario: 注册结果反馈

- **WHEN** 注册完成
- **THEN** 界面明确告知结果是成功还是失败

#### Scenario: 识别结果反馈

- **WHEN** 识别完成
- **THEN** 界面明确显示人员姓名与相似度，或醒目显示"陌生人"

### Requirement: 错误提示

系统 SHALL 将各类失败原因以使用者可理解的中文提示呈现，MUST NOT 仅抛出原始异常信息。

#### Scenario: 业务错误提示

- **WHEN** 操作因照片质量、无人脸或配额等原因失败
- **THEN** 系统以中文提示具体原因并给出可操作的建议

#### Scenario: 未预期异常

- **WHEN** 界面线程或工作线程抛出未预期的异常
- **THEN** 系统捕获该异常、向使用者提示概要信息，并保持窗口存活而不整体退出
