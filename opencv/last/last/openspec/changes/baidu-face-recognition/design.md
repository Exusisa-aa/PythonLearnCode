## Context

`opencv/last/` 目前是空目录，同级的 `opencv/` 下只有若干独立的课堂练习脚本（`classwork*.py`），它们各自调用 OpenCV 做单点演示，彼此之间没有共享状态，也没有任何一个把图像采集与云服务串成完整业务。

本次要交付的是一个**可演示、可交付的完整应用**：基于百度智能云人脸识别在线 API，实现人员注册、单人识别、陌生人判断与人脸库管理，并配一个 Tkinter 桌面界面。

已确认的外部约束：

- **百度在线 API 不返回原始人脸特征向量**。`/rest/2.0/face/v3/detect` 返回的是 `face_token`、人脸框、属性和质量信息；特征比对只能在百度侧完成。相似度分值由 `/rest/2.0/face/v3/match`（1:1）与 `/rest/2.0/face/v3/search`（1:N）返回。因此"提取人脸特征并保存"这一需求的**落地形态是"把人脸注册进百度云端人脸库并持有其 `face_token`"**，而非在本地保存一串浮点向量。
- **鉴权方式**为 `access_token`：用 AK/SK 调 `https://aip.baidubce.com/oauth/2.0/token` 换取，有效期 30 天，需拼在业务 URL 的 query 中。
- **接口配额有限**：个人认证的免费额度约为 1 QPS、每月 1000 次。设计上必须尽量减少冗余调用。
- **图片编码**：`image_type=BASE64` 时，Base64 串**不能带** `data:image/jpg;base64,` 前缀；编码后需小于 2M；支持 PNG/JPG/JPEG/BMP，不支持 GIF。
- **标识符字符集**：`group_id` / `user_id` 仅允许数字、字母、下划线，长度上限 48B。中文姓名不能直接作为 `user_id`。
- 目标运行环境为 Windows 11 + Python，使用者将自行在 `.env` 中填入 AK/SK。

## Goals / Non-Goals

**Goals:**

- 提供一个开箱即用的桌面程序：填好 `.env` 后 `python app.py` 即可运行，完成注册 → 识别 → 管理的完整闭环。
- 人员注册：输入姓名 + 摄像头采集或文件选择，人脸进入百度的脸库，本地留下可查询的档案。
- 单人识别：对摄像头画面或图片执行 1:N 检索，输出最相似人员姓名与相似度分值。
- 陌生人判断：相似度低于阈值时明确输出"陌生人"，不强行匹配。
- 人脸库管理：查看全部已注册人员、删除人员，并保证云端与本地记录一致。
- 界面在有网络请求进行时保持不卡死，并能给出明确的成功/失败反馈。

**Non-Goals:**

- 不做本地人脸特征提取与本地相似度计算（需要百度离线 SDK 授权或其他模型，见 Decisions）。
- 不做活体检测、人脸实名认证、口罩/年龄/情绪等属性展示——这些接口存在但不在本次必做功能内。
- 不做多用户账号体系、权限控制、服务端部署与多机共享。
- 不做考勤统计、打卡记录、报表导出。
- 不追求高并发；QPS 限制下按单用户交互式使用设计。

## Decisions

### 1. 人脸库放在百度云端，本地 SQLite 只存"档案"

`/search` 由百度完成特征比对并返回 `score`，本地无需也不应该复制一份特征库。

- `persons` 表字段：`user_id`（主键，ASCII）、`name`（中文姓名）、`group_id`、`face_token`（最近一次注册返回）、`photo_path`（本地留存的注册照，便于界面回显）、`created_at`、`updated_at`。
- 姓名同时写入百度侧 `user_info` 字段（上限 256B，支持中文）。识别时优先用 `/search` 返回的 `user_info` 作为姓名，本地库作为兜底与展示来源。这样即使本地数据库丢失，识别结果仍然可用。

*备选方案*：本地保存特征向量自行比对 —— 被否，因为在线 API 拿不到原始特征，必须改用百度离线 SDK（需额外授权）或换成 InsightFace/face_recognition 等本地模型，与"使用百度智能云 SDK"的要求不符。

*备选方案*：注册照片以 BLOB 存进 SQLite —— 被否，会让数据库迅速膨胀且不便在界面上直接打开查看；改为落盘到 `data/faces/` 并在表中只记录路径。

### 2. `user_id` 由姓名哈希派生

`user_id = "u" + md5(name)[:16]`。取名确定性哈希而非自增 ID 或时间戳，是为了让"同一姓名的重复注册"天然落到同一个 `user_id` 上，从而复用百度的"同一 user_id 下最多 20 张人脸"能力——同一个人多注册几张不同角度的照片，可以提升后续识别命中率。中文姓名通过 `user_info` 承载，绕开 `user_id` 的字符集限制。

*备选方案*：用拼音或自增 ID —— 拼音有重名歧义，自增 ID 无法做"按姓名判重"的幂等注册。

### 3. 注册时不额外调用 `/detect` 做前置校验

`/faceset/user/add` 本身接受 `quality_control` 与 `liveness_control` 参数，照片不合格时会直接返回 `223113`/`223114`/`223120` 等错误码。直接依赖这些返回码做提示，可以省下一次网络调用——在 1 QPS、1000 次/月的免费额度下这个节省是实质性的。

*备选方案*：先 `/detect` 拿人脸框和角度，在界面上给用户更细致的实时反馈 —— 需要实时反馈时再引入，本期不做。

### 4. Tkinter 单窗口 + `ttk.Notebook` 三页签

注册 / 识别 / 人脸库各占一个页签，共享同一个摄像头会话。

*备选方案*：OpenCV 窗口 + 键盘按键 —— 代码更短，但"点选某个人员并删除"这类操作无法优雅实现，而人脸库管理是必做功能。
*备选方案*：Flask 网页 —— 跨平台体验更好，但引入额外依赖且浏览器摄像头链路复杂，对一个单机演示程序是过度设计。

### 5. 摄像头采集与网络请求都不占用 UI 主线程

这是本设计里最容易出问题的地方，Tkinter 的 `mainloop` 必须保持响应：

- **采集**：独立采集线程执行 `cv2.VideoCapture.read()` 循环，把最新帧写入一个容量为 1 的 `queue.Queue`（满则丢弃旧帧，保证永远取到最新画面）。Tkinter 侧用 `root.after(~33ms, ...)` 定时取帧、转换并刷新 `Label`。
- **网络**：注册、识别、删除等所有 HTTP 调用都放到工作线程执行，完成后通过 `root.after(0, callback)` 把结果回投到主线程更新界面。绝不在按钮回调里直接发请求。
- **帧显示**：OpenCV 的 BGR `ndarray` 需转为 RGB 再由 `Pillow` 转成 `ImageTk.PhotoImage`。注意 `PhotoImage` 对象必须被界面对象持有引用，否则会被 GC 回收导致画面空白。

### 6. 相似度阈值默认 80，可配置

80 分是百度文档明确给出的推荐阈值。程序把它作为 `/search` 的 `match_threshold` 传入（低于该分数的候选不返回），同时本地再用同一阈值判定"识别成功 / 陌生人"。识别结果始终附带显示 `score`，让使用者能直观判断临界情况。

### 7. 百度客户端自管 token 生命周期

`BaiduFaceClient` 内部缓存 `access_token` 与其过期时间，提前刷新；当业务请求返回 `110`（token 无效）或 `111`（token 过期）时，自动重新获取 token 并重试一次。所有接口共用同一个 `requests.Session` 以复用连接。云端错误码通过一张映射表翻译成中文可读提示。

### 8. 删除操作以云端为准，失败则不删本地

删除人员时先调 `/faceset/user/delete`（`group_id` 传具体组）。只有云端返回 `error_code == 0` 才删除本地记录；云端失败时保留本地记录并向用户报错。这样本地档案不会出现"以为删了、云端还在"的假象——宁可留着让用户重试，也不要制造不一致。

## Risks / Trade-offs

- **免费配额耗尽（1 QPS / 1000 次/月）** → 注册时不冗余调用 `/detect`；token 缓存 30 天避免重复取 token；识别按钮做单击防抖，避免连点刷请求。配额用尽时百度返回 `17`/`18`/`19`，映射为明确的"配额不足"提示而不是笼统的失败。
- **`access_token` 30 天过期导致程序某天突然全失败** → 客户端自动刷新 + 对 `110`/`111` 自动重试一次；配置加载时校验 AK/SK 非空并给出明确报错。
- **无摄像头 / 摄像头被其他程序占用** → 采集线程启动失败时把状态置为不可用并在界面提示，程序降级为"仅从文件选择图片"，注册与识别功能仍然可用。
- **Tkinter 界面卡死** → 见决策 5，网络与采集全部移出主线程；所有跨线程更新一律经 `root.after` 回投。
- **中文姓名导致云端 `user_id` 非法** → 决策 2 的哈希派生从根上规避；同时对姓名长度与空值做输入校验。
- **临界相似度误判（熟人判成陌生人 / 陌生人误匹配）** → 阈值可配置；界面同时展示 `score` 与阈值，便于按实际场景调整；匹配失败（`222207`）单独映射为"未找到匹配用户"。
- **百度人脸库超 1 年未使用会被平台释放** → 属平台策略，本期不做自动保活；在 README 中说明该限制。
- **误删云端应用（appid）会导致整个人脸库失效** → 在 README 与控制台提示中明确警告，并在人脸库管理页删除单个人员时二次确认。

## Open Questions

- 是否需要将"注册照片是否落盘留存"做成开关？当前设计为默认留存（便于界面回显），若使用者不希望本地留有照片，可后续加配置项关闭。
- 是否需要把识别历史（谁、什么时间、多少分）记录成表？本期不做，但 `persons` 表的形态已为新增 `recognition_log` 表留好余地。
