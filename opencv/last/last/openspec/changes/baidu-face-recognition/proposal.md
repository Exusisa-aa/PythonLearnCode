## Why

当前 `opencv/` 目录下只有独立的课堂练习脚本（`classwork*.py`），没有任何一个把"人脸检测"真正落到"能用"的完整应用：没有人脸库、没有注册与识别闭环、没有界面。本次要实现一个基于百度智能云人脸识别 API 的**人员注册 + 单人识别 + 陌生人判断**桌面程序，把课程中学到的 OpenCV 图像采集与云服务 API 调用串成一个可演示、可交付的完整系统。

## What Changes

- 新增一个独立的 Python 桌面应用（运行目录 `opencv/last/`），提供 **Tkinter 图形界面**，包含「人员注册」「单人识别」「人脸库管理」三个功能页签。
- 新增 **百度智能云人脸 API 客户端封装**：统一处理 `access_token` 获取与缓存、图片 Base64 编码、请求发送与错误码映射。
- 新增 **人员注册** 流程：输入姓名 → 通过摄像头采集或从文件选择人脸图片 → 调用百度人脸库注册接口 → 人脸特征存入百度云端人脸库，同时本地 SQLite 记录注册档案。
- 新增 **单人识别** 流程：输入摄像头画面或图片 → 在人脸库中检索 → 输出最相似人员姓名与相似度分值。
- 新增 **陌生人判断**：相似度低于可配置阈值时输出"陌生人"而非强行匹配。
- 新增 **人脸库管理**：列出全部已注册人员（姓名、注册时间、人脸数量），支持删除单个人员（云端与本地同步删除）。
- 新增配置与运行骨架：`.env` 存放 AK/SK、`requirements.txt`、`README` 使用说明。

## Capabilities

### New Capabilities

- `baidu-face-api`: 百度智能云人脸 API 的 Python 客户端封装 —— access_token 获取与失效重试、图片 Base64 编码、人脸检测、人脸注册、人脸检索、人脸/用户删除、云端错误码到用户可读提示的映射。
- `face-registration`: 人员注册能力 —— 姓名输入与校验、人脸图片采集（摄像头/文件）、注册前置人脸质量校验、写入百度云端人脸库并持久化本地档案，处理同名与重复注册。
- `face-recognition`: 单人识别与陌生人判断能力 —— 采集待识别图片、在人脸库中检索最相似人员、按可配置阈值判定"识别成功/陌生人"、输出姓名与相似度分值、未检出人脸等异常情形的处理。
- `face-database-management`: 人脸库管理能力 —— 查询已注册人员列表、查看单个人员的人脸明细、删除人员并保证云端与本地记录一致、展示人脸库规模统计。
- `desktop-ui`: Tkinter 图形界面能力 —— 三个页签的布局与切换、摄像头实时预览、按钮操作与状态反馈、操作结果（含姓名与相似度）的展示、异常提示弹窗。

### Modified Capabilities

无。`openspec/specs/` 当前为空，本次全部为新增能力，不涉及既有需求变更。

## Impact

- **新增代码**：`opencv/last/` 下新增应用代码（GUI 层、业务层、百度 API 客户端、本地数据库访问层）与配置加载模块。
- **新增依赖**：`opencv-python`（摄像头采集与图像处理）、`requests`（HTTP 调用）、`python-dotenv`（配置读取）；GUI 与 SQLite 使用 Python 标准库 `tkinter`、`sqlite3`、`Pillow` 用于 Tkinter 中显示图像。
- **外部服务**：百度智能云人脸识别在线 API（`aip.baidubce.com`），需使用者在控制台自建应用并取得 API Key / Secret Key。接口调用计入账号配额，受 QPS 与每日免费额度限制。
- **本地数据**：新增 SQLite 数据库文件与（可选的）注册照片目录，需纳入 `.gitignore`；`.env` 中的密钥同样不得提交。
- **不影响**：`opencv/` 下既有的 `classwork*.py` 练习脚本与图片资源保持不变。
